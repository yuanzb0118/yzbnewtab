## 上下文

扩展是原生 JavaScript 的 Manifest V3 新标签页。默认路径必须在断网环境下可用，同时兼容已有 `desktopTags`、IndexedDB 背景和时钟设置。

## 目标 / 非目标

- 目标：默认首屏零第三方请求；历史图标平滑迁移；背景解码成本可控；核心交互支持窄屏和键盘。
- 非目标：拆分脚本模块、引入前端框架或自动化测试框架、离线缓存用户主动填写的任意外部图标 URL。

## 决策

- 固定图标与品牌选择器使用扩展内 SVG，字体使用系统字体栈。
- 自动网站图标优先匹配扩展内品牌 SVG；其余图标通过 `chrome.runtime.getURL('/_favicon/')` 以 128px 请求，成功后以 Blob 写入 IndexedDB。`desktopTags.icon` 仍仅保留显式自定义图标。
- 图标缓存按站点主机名分键，缓存命中时生成临时 Object URL；后台仅向 Chrome 内部 favicon 接口刷新，不引入第三方请求或主机权限。
- Google S2 图标迁移为空值，已知 Simple Icons CDN 地址迁移到本地品牌资源。
- 背景最长边按屏幕像素需求缩放且不超过 3840px，以 WebP 0.85 保存；旧背景在首次显示后的空闲阶段迁移一次。
- 分页容量由视口断点决定，调整尺寸时保持当前首个可见项目。

## 风险 / 权衡

- Chrome 本地缓存中没有 favicon 时可能返回通用图标或失败，使用确定性的本地字母图标兜底；用户在可联网状态访问站点后，Chrome favicon 更新会在后续新标签页刷新进扩展缓存。
- IndexedDB 读取是异步的，首帧先显示本地矢量图标、Chrome favicon 或字母兜底，缓存返回后再无闪烁替换。
- 本地品牌资源增加扩展包体积，但消除运行时 CDN 依赖，资源规模仍远低于浏览器扩展限制。
- 用户主动填写的外部图标仍依赖网络，这是显式选择，不为此请求广泛主机权限。

## 迁移计划

加载标签数据时规范化历史图标地址并回写一次；IndexedDB 保留 `customBg` 键，新增 `iconCache` 对象仓库并使用 `backgroundFormatVersion` 标记完成的背景迁移。任何迁移失败都继续使用旧数据并显示本地兜底。
