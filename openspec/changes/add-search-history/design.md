## 上下文

主搜索框当前直接将输入拼接到所选搜索引擎 URL 后跳转。搜索引擎菜单已经占用搜索框下方的浮层位置，新增历史层需要与其互斥，并在扩展页卸载前可靠保存记录。

## 目标 / 非目标

- 目标：本地持久化最近搜索词；支持快速复用和删除；保持鼠标、键盘和窄屏可用。
- 非目标：同步记录、按日期分组、保存原搜索引擎、导入导出或无痕模式。

## 决策

- 使用 `chrome.storage.local` 的 `searchHistory: string[]`，开发环境回退 `localStorage`。数组顺序即新旧顺序，不保存引擎或 URL。
- 搜索词经过首尾空白清理，按不区分大小写的完整词去重，新搜索移动到首位并截断为 20 条。
- 聚焦空输入时显示最近 8 条；输入时按不区分大小写的包含关系过滤并显示前 8 条；无结果时不显示空浮层。
- 历史项主按钮立即使用当前引擎搜索，独立删除按钮只更新记录；“清空全部”立即执行，不使用模态确认。
- 搜索提交先等待本地保存，保存失败则继续跳转，历史能力禁止阻塞搜索。
- 历史层与搜索框统一使用浅蓝液态玻璃语汇：高透光表面、背景模糊与饱和、细微内高光和冷色阴影；文字使用深灰蓝保证复杂背景上的可读性，边框保持低对比以避免明显白框。

## 风险 / 权衡

- 等待存储回调会在跳转前增加极短延迟，但能降低扩展页卸载导致记录未写入的概率。
- `chrome.storage.local` 不跨设备同步，符合本功能只保留本地个人数据的范围。

## 迁移计划

没有旧数据需要迁移。无效或非字符串存储项在读取时过滤；删除扩展会随扩展数据一并移除历史记录。
