## 新增需求

### 需求：本地搜索历史

系统必须在发起有效搜索前将搜索词保存到本地历史；历史必须按最新优先排列、忽略大小写去重并限制为 20 条。存储失败时禁止阻止正常搜索。

#### 场景：保存新搜索

- **当** 用户通过搜索按钮、Enter 或历史项发起非空搜索
- **那么** 系统必须将清理首尾空白后的搜索词移动到历史首位
- **并且** 必须使用当前选中的搜索引擎继续搜索

#### 场景：本地存储失败

- **当** 历史记录写入失败
- **那么** 系统必须继续发起搜索且不得产生未处理错误

### 需求：历史搜索下拉

系统必须在搜索框聚焦且存在记录时显示最近搜索；输入内容时必须按不区分大小写的包含关系过滤，并最多渲染 8 条。

#### 场景：聚焦搜索框

- **当** 搜索框获得焦点且当前输入为空
- **那么** 系统必须显示最近 8 条历史记录

#### 场景：没有匹配记录

- **当** 本地没有历史或输入内容没有匹配记录
- **那么** 系统必须关闭历史层且不得显示空面板

### 需求：历史记录管理

系统必须允许用户删除任意单条历史或一次清空全部，并立即同步本地存储和当前界面。

#### 场景：删除单条

- **当** 用户激活某条记录的删除按钮
- **那么** 系统必须只删除该记录且不得发起搜索

#### 场景：清空全部

- **当** 用户激活“清空全部”
- **那么** 系统必须立即删除所有搜索历史并关闭历史层

### 需求：可访问的历史操作

系统必须提供键盘可达、焦点清晰且与搜索引擎菜单互斥的历史交互。

#### 场景：键盘选择历史

- **当** 用户在搜索框按方向键进入历史，或通过 Tab 聚焦历史控件
- **那么** Enter 或 Space 必须使用聚焦记录搜索
- **并且** Escape 必须关闭历史层并将焦点返回搜索框

#### 场景：切换浮层

- **当** 用户打开搜索引擎菜单或历史搜索下拉
- **那么** 系统必须关闭另一个浮层，禁止二者重叠显示
